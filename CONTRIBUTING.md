# Contributing

Thank you for your interest in PoWV Protocol.

## Before contributing

- Contributions from people outside the organization require prior agreement with the maintainers, including the applicable confidentiality and intellectual-property terms, **before** any code or design material is shared.
- Report security issues privately, as described in [SECURITY.md](SECURITY.md).

## Workflow

1. Open an issue describing the change before starting substantial work.
2. Work on a dedicated branch and open a pull request against `main`.
3. Every pull request needs passing checks and a maintainer review.
4. Merge with a merge commit. Do not squash, rebase or rewrite published history.

## Specifications and claims

- Versioned specifications in the repositories are the technical source of truth. Changes to normative content, terminology or acceptance criteria require maintainer approval and a version change.
- Public material must not claim capabilities, deployments, certifications or partnerships that have not been demonstrated and documented.
- Do not publish implementation details, cryptographic profiles, data formats or parameters that are marked restricted.

## Never commit

- Private keys, tokens, passwords or `.env` files with real values.
- Personal data or third-party confidential material.
